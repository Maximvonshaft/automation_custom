# v4.2 Security Boundary

## Purpose

This document defines the security boundary for the v4.2 Controlled Operator Package. The goal is to prevent uncontrolled copying, reverse engineering, unauthorized execution, and country-pack leakage while preserving operator usability.

## Security posture

The v4.2 operator package must be treated as an untrusted-edge runtime. Operators and local third parties may have filesystem access to the client machine. Therefore, anything shipped locally must be assumed inspectable, copyable, and modifiable unless compiled, signed, remote-controlled, and revocable.

The core security principle is:

```text
Local Agent executes signed jobs only.
Control Plane owns compilation authority.
Country Pack stays server-side.
Operator Package contains no source-level business logic.
```

## Protected assets

The following assets must not be distributed to operators or third parties:

- country pack contents;
- field coordinates;
- dropdown rules;
- SafeBrake policy internals;
- broker authorization values;
- production credentials;
- customer manifests with real AWB / names / phone / address;
- signing private keys;
- server-side tenant config;
- source tree for production operator distribution.

## Trust boundaries

### Server-side trusted boundary

The Control Plane is trusted to:

- parse manifests;
- build declaration models;
- resolve tenant configuration;
- apply country pack logic;
- compile signed job plans;
- sign with private keys;
- revoke machines;
- record audit logs;
- manage release allowlists.

### Local semi-trusted boundary

The local Operator Client / Agent may:

- hash uploaded files;
- perform superficial file shape checks;
- validate signed job plans;
- execute allowed GUI actions;
- generate evidence bundles;
- upload or reference evidence.

The local package must not be able to produce executable job plans from Excel without the Control Plane.

### Operator boundary

Operators may:

- drag/import Excel;
- select a run;
- confirm ASYCUDA foreground readiness;
- export or upload evidence.

Operators must not be able to:

- view or edit coordinates;
- view or edit country pack logic;
- bypass signed job validation;
- trigger finalizing actions;
- run expired jobs;
- run jobs for a different tenant/machine.

## Required controls

### 1. Signed-job-only execution

The Local Agent must reject any unsigned, expired, tenant-mismatched, machine-mismatched, unsupported-mode, or forbidden-action job.

Mandatory checks:

- Ed25519 signature valid;
- `tenant_id` equals local config;
- `machine_id` equals local config;
- `mode` in `fillOnly`, `safeBrakeStore`;
- `expires_at` not expired;
- every action in allowed schema;
- no Submit/Register/Payment/tax-finalizing actions.

### 2. No local compilation

The Operator Client may compute a file hash and run superficial precheck. It must not transform Excel rows into executable click/paste/store steps.

### 3. No country pack in local artifact

The release package must not include:

- `control_plane/packs/` production content;
- real Albania coordinates beyond test fixtures;
- country mapping YAML/JSON;
- server-side SafeBrake policy files.

### 4. Machine binding

Every operator machine must have a stable machine identifier and registration state. The signed job must be bound to the machine identifier. Revocation must make future job issuance impossible and should make cached jobs short-lived enough to reduce exposure.

### 5. Short-lived jobs

Signed job plans must be short-lived. Expired jobs must fail closed before GUI execution.

### 6. Evidence integrity

Evidence must include hashes for the job plan, ledger, screenshots, parse report, declaration model, and manifest input. Evidence should be immutable after creation, or at minimum hash-addressed in Control Plane.

### 7. Release artifact integrity

Operator packages must have:

- version string;
- checksum;
- build manifest;
- source commit reference;
- release gate status;
- approved distribution list;
- rollback plan.

## Threat model

| Threat | Risk | Control |
|---|---|---|
| Third party copies green ZIP | Source and pack leakage | No source distribution; compiled/minimal package only |
| Operator extracts coordinates | Business logic leakage | Country pack server-side only |
| Local user edits job plan | Unauthorized actions | Signature verification |
| Expired job is replayed | Unauthorized stale execution | Expiry check |
| Job used on another machine | Unauthorized machine reuse | Machine binding |
| Operator compiles from Excel offline | Loss of HQ control | No local compiler |
| Submit/payment automation added accidentally | Compliance and cost risk | Forbidden action gate and tests |
| Screenshots leak customer data | Privacy risk | Hash-only external references; redaction review |
| Reverse engineering compiled client | IP leakage | Minimize embedded logic; remote compilation; revocation |
| Control Plane key leak | Full signing compromise | Server-side secret store, key rotation, audit |

## Non-negotiable boundaries

- No Submit/Register/Payment/tax-finalizing automation.
- No country pack content under `agent/`.
- No production credentials in repo or local package.
- No real customer data in tests.
- No external package release from this planning PR.
- No runtime behavior changes in this planning PR.

## Approval requirement

A later v4.2 implementation cannot be considered external-release-ready until security review confirms the local artifact contains no server-side pack logic and cannot execute anything beyond signed allowed actions.
