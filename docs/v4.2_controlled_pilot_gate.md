# v4.2 Controlled Pilot Gate

## Purpose

Milestone 7 defines the final gate before a controlled internal pilot package can be considered.

This gate is not a production approval and is not an external rollout approval. It records whether a candidate package has enough traceability, checksums, allowlists, quality evidence, and rollback information to be reviewed by HQ.

## Scope

In scope:

- candidate package root verification;
- build manifest presence check;
- checksum file presence check;
- operator allowlist reference;
- machine allowlist reference;
- quality evidence flags;
- owner approval fields;
- boundary flags proving no source tree, no local pack content, no local Excel compiler, and no raw sensitive evidence;
- `PILOT_GATE_RECORD.json` creation.

Out of scope:

- creating an installer;
- external distribution;
- network upload;
- production credential handling;
- country pack inclusion;
- local Excel-to-executable-plan compilation;
- final customs submission automation.

## Gate command

```powershell
.\packaging\windows_operator\pilot_gate_record.ps1 `
  -CandidatePackageRoot .\dist\CustomsOpsOperatorSkeleton `
  -CandidateVersion "0.0.0-pilot-candidate" `
  -SourceCommit "<40-char-main-commit-sha>" `
  -OperatorAllowlist .\packaging\windows_operator\operator_allowlist.example.json `
  -MachineAllowlist .\packaging\windows_operator\machine_allowlist.example.json `
  -LocalQualityGatePassed `
  -RemoteQualityGatePassed:$false `
  -BusinessOwner "" `
  -ComplianceOwner "" `
  -SupportOwner "" `
  -TechnicalOwner ""
```

The script writes:

```text
<CandidatePackageRoot>\PILOT_GATE_RECORD.json
```

## Required candidate package files

The candidate root must contain:

```text
BUILD_MANIFEST.json
checksums.sha256
```

The build manifest must confirm:

```json
{
  "no_finalization_actions": true,
  "country_pack_excluded": true,
  "local_compilation_disabled": true
}
```

## Approval fields

The gate record has placeholders for:

- business owner;
- compliance owner;
- support owner;
- technical owner.

Empty owner fields mean the gate record is not approved for a real pilot.

## Boundary flags

The gate record must always keep:

```json
{
  "source_tree_distributed": false,
  "country_pack_included": false,
  "local_compilation_enabled": false,
  "external_distribution_approved": false,
  "raw_sensitive_evidence_included": false
}
```

## Exit criteria

A candidate may be reviewed only when:

- local quality gates pass;
- checksum file exists;
- build manifest source commit matches the requested source commit;
- operator allowlist exists;
- machine allowlist exists;
- rollback/disable instructions are available;
- evidence reference model is available;
- separate human approval is recorded.

## Non-approval statement

Merging the M7 PR only adds the gate mechanism. It does not approve any external rollout or production usage.
