# v4.2 Implementation Roadmap

## Purpose

This roadmap decomposes v4.2 Controlled Operator Package into implementation milestones. This planning PR does not implement runtime behavior. Each milestone should be delivered through focused PRs with isolated acceptance criteria.

## Current baseline

- v4.1 is an internal Release Candidate.
- Windows ASYCUDA Lab Smoke passed under SafeBrake.
- Excel manifest intake supports current Albania baseline and non-merge frontline template regression.
- Signed job plan validation exists.
- Windows GUI executor path exists.
- Evidence bundle path exists.
- External operator package is not approved.

## Milestone 0: Planning pack

Status: this PR.

Deliverables:

- v4.2 controlled package plan;
- security boundary;
- acceptance criteria;
- release packaging checklist;
- file-level implementation roadmap.

Non-scope:

- runtime code;
- executable installer;
- external release.

## Milestone 1: Packaging boundary audit

Goal: prove what must and must not enter the local package.

Expected work:

- identify package entrypoints;
- classify files as local-safe, server-only, test-only, or excluded;
- add package exclusion manifest;
- add tests that assert country pack production content is absent from local package;
- add tests that assert `control_plane/packs` does not ship with operator artifact.

Candidate files:

- `docs/v4.2_package_file_classification.md`
- `packaging/operator_package_manifest.json`
- `tests/test_operator_package_boundaries.py`

## Milestone 2: Operator package skeleton

Goal: define a local package structure without releasing it externally.

Expected work:

- create Windows package layout;
- define launcher entrypoint;
- include operator runbook;
- include support diagnostics command;
- exclude country pack and server config;
- generate build manifest and checksum.

Candidate files:

- `packaging/windows_operator/README.md`
- `packaging/windows_operator/build_manifest.schema.json`
- `packaging/windows_operator/package.ps1`
- `scripts/operator_support_diagnostics.ps1`

## Milestone 3: Machine registration design implementation

Goal: bind operator package to machine identity and tenant.

Expected work:

- define machine identity contract;
- define registration request model;
- define registration response model;
- define local machine config storage boundary;
- ensure machine_id is used during signed job verification;
- define revoke semantics.

Candidate files:

- `shared/schemas/machine_registration.schema.json`
- `agent/customsops_agent/machine_identity.py`
- `docs/v4.2_machine_registration.md`
- `tests/test_machine_registration_contract.py`

Implementation must not include production secrets.

## Milestone 4: Signed-job-only operator flow

Goal: ensure the operator package can only run HQ-issued signed jobs.

Expected work:

- harden signed job import path;
- reject unsigned local JSON plans;
- reject expired / wrong tenant / wrong machine / unsupported mode / forbidden actions;
- ensure operator drag/drop path cannot emit executable steps;
- document offline behavior.

Candidate files:

- `agent/customsops_agent/operator_flow.py`
- `tests/test_operator_signed_job_only.py`
- `docs/v4.2_signed_job_only_flow.md`

## Milestone 5: Operator UX shell

Goal: provide a simple operator workflow while preserving security boundaries.

Expected work:

- CLI or simple GUI shell for drag/import manifest;
- precheck status display;
- run signed job command;
- evidence folder open/export;
- clear SafeBrake mode warning;
- no plan editor;
- no country pack viewer.

Candidate files:

- `agent/customsops_agent/operator_cli.py`
- `docs/v4.2_operator_ux_spec.md`
- `tests/test_operator_cli_contract.py`

## Milestone 6: Evidence upload/reference model

Goal: move from local bundle only to controlled HQ reference flow.

Expected work:

- define evidence reference schema;
- define evidence upload API contract or manual hash-reference workflow;
- define redaction and sensitive screenshot rules;
- add support diagnostics metadata;
- ensure evidence hash is stable.

Candidate files:

- `shared/schemas/evidence_reference.schema.json`
- `docs/v4.2_evidence_reference_model.md`
- `tests/test_evidence_reference_contract.py`

## Milestone 7: Controlled pilot package release gate

Goal: create a release process for internal pilot package.

Expected work:

- package build script;
- checksum generation;
- release note template;
- pilot approval template;
- rollback instruction;
- machine/operator allowlist.

Candidate files:

- `docs/v4.2_pilot_release_gate.md`
- `docs/v4.2_operator_package_release_note_template.md`
- `packaging/windows_operator/release.ps1`

## Milestone sequencing

Recommended order:

1. Packaging boundary audit.
2. Operator package skeleton.
3. Machine registration contract.
4. Signed-job-only hardening.
5. Operator UX shell.
6. Evidence reference model.
7. Internal pilot package release gate.

Do not begin external distribution before all milestones pass review.

## Validation command set

Every implementation PR must run:

```text
python 15_automation_scripts/validate_pack.py
python -m ruff check .
python -m pytest -q
python -m bandit -q -r agent control_plane shared
```

Package-specific PRs must add relevant packaging tests and hash/release evidence.

## Exit criteria for v4.2

v4.2 may be considered `Controlled Operator Package Candidate` only when:

- package boundary audit passes;
- local artifact excludes server-only pack content;
- signed-job-only execution is tested;
- machine binding is tested;
- evidence reference path is tested;
- packaging checklist is complete;
- no-finalization boundary remains enforced;
- a separate release approval issue records artifact hashes and target pilot machines.
