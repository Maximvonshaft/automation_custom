# v4.2 Operator UX Shell

## Purpose

Milestone 5 adds a minimal operator-facing CLI shell around the signed-job-only local execution boundary.

The goal is not to create a full desktop product yet. The goal is to give operators and support staff a controlled, inspectable workflow:

1. check local readiness;
2. run superficial Excel manifest precheck;
3. run an HQ-issued signed job plan;
4. receive a local evidence bundle path.

## Boundary

The shell is intentionally narrow.

It may:

- inspect local machine registration status;
- verify that a trusted public key is configured;
- compute a manifest file hash;
- check that a workbook is a ZIP-based Excel container with `xl/workbook.xml`;
- call the existing signed-job-only operator flow;
- open or print the evidence bundle path.

It must not:

- parse Excel rows into customs declarations;
- compile executable GUI steps from local Excel files;
- expose country pack content, field coordinates, dropdown rules, or SafeBrake policy internals;
- edit signed plans;
- generate signatures;
- store production ASYCUDA credentials;
- run Submit/Register/Payment/tax-finalizing automation.

## Commands

### Status

```powershell
python -m agent.customsops_agent.operator_cli status `
  --machine-registration .\machine_registration.json `
  --public-key-pem .\trusted_public_key.pem
```

Expected output is JSON containing:

- machine registration load status;
- active/rejected status;
- tenant_id and machine_id when loaded;
- public key availability;
- `ready_for_signed_job`;
- hard boundary flags.

### Manifest precheck

```powershell
python -m agent.customsops_agent.operator_cli precheck-manifest `
  --manifest .\manifest.xlsx `
  --output-json .\evidence\precheck.json
```

This command only performs local superficial precheck:

- file exists;
- file is a regular file;
- suffix is `.xlsx` or `.xlsm`;
- SHA-256 hash can be computed;
- ZIP container integrity is valid;
- `xl/workbook.xml` exists.

It does not parse rows, detect headers, apply Albania mapping, read country packs, or emit executable actions.

### Run signed job

```powershell
python -m agent.customsops_agent.operator_cli run-signed-job `
  --signed-job-plan .\signed_job_plan.json `
  --machine-registration .\machine_registration.json `
  --public-key-pem .\trusted_public_key.pem `
  --evidence-root .\evidence\operator `
  --foreground-window-title "ASYCUDAWorld" `
  --real-gui `
  --open-evidence-folder
```

For dry/mock verification, omit `--real-gui` and `--foreground-window-title`.

## Failure behavior

The shell fails closed when:

- machine registration is missing;
- machine registration is pending, revoked, disabled, or invalid;
- trusted public key is missing;
- manifest file is missing, unsupported, empty, corrupt, or not an Excel workbook;
- signed job validation fails in the downstream operator flow;
- real GUI mode is requested without foreground window title.

## Acceptance criteria

- `agent/customsops_agent/operator_cli.py` exists.
- Status command exposes readiness and boundary JSON.
- Manifest precheck computes hash but does not parse rows or compile actions.
- Signed job command delegates to `operator_flow.run_operator_signed_job(...)`.
- Tests prove the CLI shell does not expose a plan editor, country pack viewer, or local Excel compiler.
- Tests prove manifest precheck rejects unsupported file types and accepts valid Excel containers superficially.
- Tests prove status fails closed for non-active machine registration.

## Release note

This shell is still not an external deployment approval. It is a controlled UX milestone before evidence reference and pilot release gates.
