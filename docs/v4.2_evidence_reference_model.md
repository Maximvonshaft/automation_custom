# v4.2 Evidence Reference Model

## Purpose

Milestone 6 defines a reference-only evidence model for controlled HQ review.

The goal is to let an operator or support workflow produce a stable metadata record that identifies a local evidence bundle without committing or uploading raw screenshots, ledgers, manifests, or support diagnostics content into the repository.

## Current boundary

This milestone implements local evidence reference generation only.

It does not implement:

- network upload;
- HQ API storage;
- screenshot content transfer;
- automatic redaction;
- production release approval;
- final customs submission automation.

## Input

The command expects a local evidence ZIP produced by the Local Agent. The ZIP must contain:

```text
evidence_manifest.json
```

The evidence manifest is read only to extract run metadata and artifact hash references.

## Output

The reference JSON includes:

- `evidence_reference_id`;
- `evidence_reference_sha256`;
- run context: tenant, machine, job, run, mode, pack, agent version;
- evidence bundle file name, size, and SHA-256;
- evidence manifest SHA-256;
- artifact hashes from the evidence manifest;
- bundle entry names;
- screenshot artifact hash references;
- optional support diagnostics manifest hash;
- policy flags proving reference-only behavior.

The output does not include raw artifact content.

## Operator command

```powershell
python -m agent.customsops_agent.operator_cli reference-evidence `
  --evidence-bundle .\evidence\operator\tenant_demo\job_demo\run_x.zip `
  --output-json .\evidence\operator\tenant_demo\job_demo\run_x_reference.json
```

With support diagnostics manifest reference:

```powershell
python -m agent.customsops_agent.operator_cli reference-evidence `
  --evidence-bundle .\evidence\operator\tenant_demo\job_demo\run_x.zip `
  --support-diagnostics-manifest .\support_diagnostics_manifest.json `
  --output-json .\evidence\operator\tenant_demo\job_demo\run_x_reference.json
```

## Security controls

The reference model enforces:

```json
{
  "reference_only": true,
  "raw_artifacts_uploaded": false,
  "screenshot_content_included": false,
  "requires_hq_review": true
}
```

Screenshot artifacts are represented by file name and SHA-256 only. They are marked as requiring redaction before upload.

## Acceptance criteria

- `shared/schemas/evidence_reference.schema.json` exists.
- `agent/customsops_agent/evidence_reference.py` can build reference-only metadata from a valid evidence ZIP.
- Operator CLI exposes `reference-evidence`.
- Tests prove raw screenshot content is not embedded.
- Tests prove missing evidence manifest fails closed.
- Tests prove support diagnostics are referenced by hash only.
- No network upload API is added in this milestone.

## Follow-up

A later milestone or PR may add a controlled HQ API contract. That future API must preserve this boundary: metadata first, raw screenshot upload only after separate redaction and approval rules are implemented.
