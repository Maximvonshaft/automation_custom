# v4.2 Controlled Operator Package Plan

## Status

`v4.1` is an internal Release Candidate. It has passed local quality gates, remote `SSS Quality Gate`, and Windows ASYCUDA Lab Smoke evidence under SafeBrake. This document defines the next-stage `v4.2` planning scope only.

This is not an external deployment approval. This document does not authorize source distribution, operator package release, Submit/Register/Payment automation, or movement of country pack content into the local Agent.

## Objective

Convert the current internal release-candidate implementation into a controlled operator package model where operators can run supervised ASYCUDA foreground automation without receiving the source tree, country packs, coordinates, business mapping, or SafeBrake policy internals.

The business objective is control: HQ must keep ownership of templates, country pack logic, job compilation, authorization, revocation, evidence review, and release governance.

## Target operator workflow

```text
Operator Client
  -> drag/import Excel manifest
  -> local precheck only: file type, hash, shape, environment status
  -> send manifest or normalized rows to Control Plane
  -> Control Plane parses and validates manifest
  -> Control Plane builds declaration_model
  -> server-side country pack compiles a short-lived signed job plan
  -> Operator Client receives signed job plan only
  -> Local Agent validates signature, tenant, machine, mode, expiry, and allowed actions
  -> Local Agent executes ASYCUDA foreground GUI in fillOnly or safeBrakeStore mode
  -> evidence bundle is generated locally and uploaded or referenced to HQ
  -> HQ reviews hashes, run metadata, screenshots, and support diagnostics
```

## Architecture layers

### 1. Operator Client

The Operator Client is the human-facing shell. It may provide drag/drop manifest intake, precheck status, run status, and evidence export. It must not include country pack content or compile executable plans.

Allowed responsibilities:

- accept Excel file input;
- compute file hash;
- run local shape precheck;
- show environment readiness;
- receive signed job plans from Control Plane;
- invoke the Local Agent execution boundary;
- package evidence and diagnostic references.

Forbidden responsibilities:

- compile executable job plans from Excel;
- contain country pack, coordinates, business rules, dropdown rules, or SafeBrake policy internals;
- trigger Submit/Register/Payment/tax-finalizing automation;
- store production ASYCUDA credentials.

### 2. Control Plane

The Control Plane owns compilation authority. It converts manifest input into declaration model and signed job plans using server-side tenant config and country packs.

Required responsibilities:

- tenant and machine registration;
- manifest parsing and validation;
- declaration_model creation;
- country pack and tenant config resolution;
- short-lived signed job plan compilation;
- evidence intake/reference;
- audit log;
- machine revoke/disable path;
- release version allowlist.

### 3. Local Agent

The Local Agent is the controlled execution boundary. It executes only signed job plans that pass local verification.

Required responsibilities:

- verify Ed25519 signature;
- verify tenant_id and machine_id;
- verify mode is `fillOnly` or `safeBrakeStore`;
- verify expiry;
- reject forbidden actions;
- require ASYCUDA foreground confirmation;
- execute click/paste/hotkey/screenshot/store_line_safebrake actions;
- generate ledger, screenshots, run_context, signed_job_plan copy, and evidence bundle.

### 4. Evidence subsystem

The evidence subsystem is a release and support artifact, not just logs.

Minimum evidence contents:

- input manifest hash;
- parse report hash;
- declaration model hash;
- signed job plan hash;
- ledger hash;
- screenshot hash summary;
- run context;
- machine_id, tenant_id, job_id, mode, pack_version;
- SafeBrake outcome;
- known issues;
- no-finalization boundary confirmation.

## v4.2 scope

In scope:

- controlled Windows operator package design;
- no-source/no-pack distribution strategy;
- machine binding and registration design;
- signed-job-only execution model;
- operator drag/drop UX design;
- evidence upload/reference model;
- release packaging checklist;
- threat model;
- file-level implementation roadmap;
- acceptance criteria.

Out of scope:

- Submit/Register/Payment/tax-finalizing automation;
- country pack inside `agent/`;
- local Excel-to-executable-plan compilation;
- external production deployment approval;
- full billing/settlement;
- production credential storage;
- multi-country expansion beyond current Albania baseline;
- runtime code changes in this planning PR.

## Decision gates

`v4.2` cannot be released externally until all gates are satisfied:

1. no source distribution path;
2. no country pack in local artifact;
3. local Agent can execute signed jobs only;
4. machine binding and revocation are defined and tested;
5. packaging process is reproducible;
6. evidence bundle schema is stable;
7. operator package has version and checksum;
8. SafeBrake remains the default validation mode;
9. no Submit/Register/Payment/tax-finalizing actions exist;
10. release approval is recorded separately from implementation merge.
