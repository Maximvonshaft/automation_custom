# v4.2 Release Packaging Checklist

## Purpose

This checklist governs any future v4.2 Controlled Operator Package release. It is not a release approval by itself. It defines what must be true before a package can be offered to an operator, agent, broker, or third party.

## Pre-release classification

Before packaging, confirm the intended release type:

- internal lab package;
- internal pilot package;
- controlled operator package candidate;
- external operator pilot package;
- production operator package.

The current v4.2 planning PR targets only future planning. It does not approve external packaging.

## Source and content controls

- [ ] Package is not a raw repository source tree.
- [ ] Package does not include `control_plane/packs/` production content.
- [ ] Package does not include field coordinate maps as editable YAML/JSON.
- [ ] Package does not include dropdown rules or country business mapping.
- [ ] Package does not include SafeBrake policy internals as editable config.
- [ ] Package does not include signing private keys.
- [ ] Package does not include production ASYCUDA credentials.
- [ ] Package does not include real customer Excel, AWB, phone, address, or screenshot data.

## Build controls

- [ ] Build is reproducible from an identified source commit.
- [ ] Build manifest includes repository, commit SHA, branch, timestamp, package version, and builder identity.
- [ ] Package checksum is produced.
- [ ] Artifact hash is recorded in release evidence.
- [ ] Dependency list is recorded.
- [ ] Windows target version is recorded.
- [ ] Python/runtime embedding strategy is documented if applicable.

## Execution controls

- [ ] Local Agent executes signed job plans only.
- [ ] Expired job plan fails closed.
- [ ] Wrong tenant fails closed.
- [ ] Wrong machine fails closed.
- [ ] Unsupported mode fails closed.
- [ ] Forbidden actions fail closed.
- [ ] ASYCUDA foreground confirmation is required.
- [ ] Runtime modes are limited to `fillOnly` and `safeBrakeStore`.
- [ ] Submit/Register/Payment/tax-finalizing automation is absent.

## Machine controls

- [ ] Machine registration process is defined.
- [ ] Machine identifier is stable enough for signed-job binding.
- [ ] Machine revocation process is defined.
- [ ] Operator package refuses or warns on unregistered machine.
- [ ] Revoked machine cannot receive new job plans.
- [ ] Cached job lifetime is short enough to limit post-revocation exposure.

## Evidence controls

- [ ] Evidence bundle contains run_context.
- [ ] Evidence bundle contains ledger.
- [ ] Evidence bundle contains signed_job_plan copy.
- [ ] Evidence bundle contains manifest_parse_report or reference.
- [ ] Evidence bundle contains declaration_model or reference.
- [ ] Evidence bundle contains screenshot hashes.
- [ ] Evidence bundle includes no unreviewed sensitive screenshots in repository.
- [ ] Evidence upload/reference path is documented.
- [ ] Evidence retention policy is documented.

## Operator UX controls

- [ ] Operator sees simple drag/import flow.
- [ ] Operator sees precheck result before execution.
- [ ] Operator sees mode clearly: `fillOnly` or `safeBrakeStore`.
- [ ] Operator sees explicit warning that final customs submission is not automated.
- [ ] Operator can open evidence folder.
- [ ] Operator can export support diagnostics without exposing secrets.
- [ ] Operator cannot edit executable steps.
- [ ] Operator cannot view country pack internals.

## Support controls

- [ ] Support diagnostics bundle is defined.
- [ ] Diagnostics exclude credentials and sensitive customer content by default.
- [ ] Failure categories are documented: environment, ASYCUDA foreground, signature, job expiry, GUI execution, evidence creation.
- [ ] Rollback/uninstall process is documented.
- [ ] Emergency disable process is documented.

## Release gate

Before any external operator pilot:

- [ ] All local tests pass.
- [ ] Remote `SSS Quality Gate` passes.
- [ ] Windows lab smoke remains passing.
- [ ] Security review confirms no country pack leakage.
- [ ] Operator package review confirms no source tree leakage.
- [ ] Business owner approves distribution target.
- [ ] Compliance owner approves evidence handling.
- [ ] Support owner approves support runbook.
- [ ] Release owner approves artifact checksum and version.

## Explicit non-approval statement

Merging a planning or implementation PR does not approve external distribution. External distribution requires a separate release approval record with artifact hash and target machine/operator list.
