# v4.2 Operator Package Acceptance Criteria

## Status definition

The v4.2 Controlled Operator Package is acceptable only when it converts the v4.1 internal Release Candidate into a controlled, non-source, signed-job-only operator package. Approval of these criteria does not authorize Submit/Register/Payment/tax-finalizing automation.

## Functional acceptance criteria

### Operator intake

- Operator can select or drag an Excel manifest into the Operator Client.
- Operator Client computes file hash.
- Operator Client performs local superficial precheck only.
- Operator Client cannot compile executable GUI steps locally.
- Invalid file type or malformed workbook produces clear operator-facing error.

### Control Plane integration

- Manifest or normalized rows can be sent to the Control Plane.
- Control Plane parses and validates manifest.
- Control Plane builds declaration_model.
- Control Plane compiles signed job plan using server-side tenant config and country pack.
- Signed job plan is short-lived and bound to tenant and machine.

### Local Agent execution

- Local Agent accepts signed job plan only.
- Local Agent rejects unsigned, expired, tampered, wrong-tenant, wrong-machine, wrong-mode, or forbidden-action jobs.
- Local Agent supports only `fillOnly` and `safeBrakeStore` modes.
- Local Agent requires ASYCUDA foreground confirmation before GUI execution.
- Local Agent preserves existing v4.1 Windows GUI executor and SafeBrake behavior.

### Evidence

- Every run generates an evidence bundle.
- Evidence includes hashes for manifest input, parse report, declaration model, signed job plan, ledger, and screenshots.
- Evidence includes run_context with tenant_id, machine_id, job_id, mode, pack_version, and timestamp.
- Evidence can be uploaded or referenced to HQ without committing sensitive screenshot content to repository.

## Security acceptance criteria

- Operator package does not contain country pack production content.
- Operator package does not contain field coordinates or dropdown rules except non-sensitive test fixtures approved for local tests.
- Operator package does not include signing private keys.
- Operator package does not include real customer data.
- Operator package is not a raw source tree ZIP.
- Local Agent cannot compile executable plans from Excel.
- Local Agent cannot run Submit/Register/Payment/tax-finalizing actions.
- Machine registration and revocation design is documented before external release.
- Package checksum and build manifest are produced before external release.

## Packaging acceptance criteria

- Package has a version.
- Package has a checksum.
- Package has a build manifest referencing source commit.
- Package has a release gate record.
- Package has an operator runbook.
- Package has a support diagnostics runbook.
- Package has a rollback/uninstall path.
- Package explicitly states it is not approved for finalizing customs submission actions.

## Testing acceptance criteria

Minimum tests for a future implementation PR:

- local package contains no country pack production content;
- local Agent rejects locally compiled jobs;
- signed job validation rejects tampered job;
- signed job validation rejects expired job;
- signed job validation rejects wrong tenant;
- signed job validation rejects wrong machine;
- signed job validation rejects unsupported mode;
- signed job validation rejects forbidden action;
- manifest precheck does not output executable steps;
- evidence bundle contains required files and hashes;
- Windows smoke run remains SafeBrake-only unless separate release gate approves a broader mode.

## Documentation acceptance criteria

Future implementation must update:

- operator runbook;
- admin/HQ runbook;
- machine registration process;
- evidence review process;
- support diagnostics process;
- release packaging checklist;
- threat model.

## Non-acceptance criteria

The following conditions make v4.2 unacceptable:

- source tree distributed to operators;
- country pack shipped to local package;
- local Excel-to-executable-plan compiler shipped;
- Submit/Register/Payment/tax-finalizing actions added;
- package lacks revocation path;
- package lacks evidence output;
- package uses real customer data in tests or examples;
- package cannot prove which commit produced it;
- package cannot be rolled back or disabled.

## Release classification

Passing these criteria means the project may be promoted to `v4.2 Controlled Operator Package Candidate`.

It does not mean production external rollout is approved. External rollout requires separate business, compliance, support, and operational approval.
