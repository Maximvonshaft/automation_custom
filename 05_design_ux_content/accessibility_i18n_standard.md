# Accessibility and i18n Standard

## Accessibility

- Keyboard navigation must work for critical workflows.
- Buttons and inputs need accessible labels.
- Color must not be the only state indicator.
- Focus states must be visible.
- Modal/dialog actions must be reachable and dismissible.
- Error messages must be associated with fields where applicable.

## i18n

- User-facing copy should not be hardcoded if the app has i18n.
- Avoid mixed language unless product intentionally uses bilingual labels.
- Avoid untranslated technical enum values.
- Date/time/number formatting should follow locale conventions.
